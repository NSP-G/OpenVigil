# OpenVigil

OpenVigil 是一个 Windows 桌面小工具：选定一个**已打开的窗口**（比如教室监控客户端窗口），
定时抓取它的画面，交给**智谱视觉大模型**（全免费模型）自动巡检，发现异常时弹桌面通知提醒。

数据流全程本地：窗口抓取、画面变化检测、图片压缩都在本机完成；只有画面出现变化时，
才把图片以 base64 内联在请求体中发给智谱官方 API，**不经过任何云存储或中转服务**。

> 本项目定位为**辅助巡检、减少人工盯屏**，异常终判请务必由老师人工确认。

## 特性

**基础巡检**

- **选窗口抓取**：枚举当前所有打开的窗口，选一个盯它（用 `PrintWindow`，被遮挡也能抓）
- **本地变化检测**：画面没变化就跳过 API 调用，省 token、省流量
- **双意见视觉判定**：初判报异常后，取一次**独立第二意见**复核，而非用诱导性提示词自我否定
- **本地兜底守卫**：模型判「正常」但画面相对本场景基线显著异常时给出待确认提示
- **桌面通知**：达到置信度阈值才弹通知，且两次告警之间有最小间隔，避免刷屏
- **自检按钮**：一键诊断配置、API 连通性、模型判定力、端到端演练六项，失败项给出修复建议
- **告警历史**：独立栏目记录每条告警的时间、类型、置信度与截图，支持放大查看
- **深浅色主题**：浅色 / 深色 / 跟随系统三档，跟随系统时实时响应系统切换

**v0.3 新增：让 AI 看得懂过程，而不是只看照片**

- **多轮复演**：初判要告警时不直接报，而是请四位角色（行为观察员 / 情境解读员 / 时序推演员 / 审慎质疑员）各自独立看一遍并投票
- **外部记忆系统**：AI 把观察到的事实写入本地 Markdown 记忆，下次判定时带着这些记忆一起看——墙上新贴了通知、某片区域一直安静，它都记得
- **场景变化检测**：能识别「墙上多了张表」「桌椅挪了」这类**持久性变化**，而不只是「画面动了」
- **先描述再判断**：强制模型先说清「我看到了什么」，再下结论——编不出合理解释，它自己就会判正常
- **七类判定**：正常上课 / 有序活动 / 聚集围观 / 打闹冲突 / 离座走动 / 注意力涣散 / 其他，替代粗糙的「异常 / 正常」二选一
- **事件生命周期**：聚集是在**形成**还是在**消散**，持续时间本身就是判据

> **全自主**：以上能力全部开箱即用，不需要老师预先标注座位表或学生名单。
> 系统默认按位置记录（3 排 2 座），有人名信息时自动增强。

## 环境要求

- Windows 10 / 11
- Python 3.10+

## 安装

```bash
pip install -r requirements.txt
```

## 配置

1. 到 [智谱开放平台 open.bigmodel.cn](https://open.bigmodel.cn) 注册并创建 API Key
2. 编辑 `config.json`，把 `api_key` 填进去

> **安全提示**：`config.json` 会被 Git 跟踪。填写 Key 后请勿把该文件提交到任何公开仓库——
> 建议在本机执行 `git update-index --skip-worktree config.json`，或在 `.gitignore` 中忽略它。

关键配置项：

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `capture_interval_sec` | 抓帧间隔（秒） | 5 |
| `activity_trigger` | 本地活动度门控，低于此值且未到心跳周期则跳过 API | 0.12 |
| `heartbeat_frames` | 连续多少帧没做视觉分析就强制分析一次 | 20 |
| `alert_confidence` | 告警置信度阈值（0~1） | 0.45 |
| `min_alert_interval_sec` | 两次弹窗通知的最小间隔（秒） | 20 |
| `keep_frames` | 是否把告警帧存到本地 `alerts/` | false |
| `local_guard_enabled` | 是否启用本地兜底守卫 | true |
| `local_guard_cooldown_sec` | 兜底提示的冷却时间（秒） | 300 |
| `multi_frame_confirm` | 聚集/打闹类场景追问「在聚还是在散」 | true |
| `deliberation_enabled` | 初判要告警时是否启动多轮复演 | true |
| `memory_root` | 外部记忆存放目录 | memory |
| `memory_max_chars` | 记忆总字符上限，超限自动压缩 | 4000 |
| `theme` | 界面主题：`auto` / `light` / `dark` | auto |

## 使用

### 图形界面（推荐）

```bash
python gui/main_gui.py
```

- **左栏**：窗口列表（支持关键字过滤），点击选中监控窗口
- **中栏**：实时画面预览、抓帧/AI调用/跳过/告警四项统计、开始/停止/测试一次
- **右栏**：「巡检控制」与「告警历史」两个标签页，历史页自动刷新
- **顶栏齿轮**：设置面板（API Key、抓帧间隔、阈值、主题），内含「运行自检」按钮
- 动画由本地 GSAP 提供（无外链），遵循系统「减弱动态效果」设置

### 命令行（备用）

```bash
python main.py              # 交互选择窗口，持续巡检
python main.py --list       # 只列出窗口
python main.py --title 监控  # 按标题关键字自动选窗口
python main.py --once       # 选窗口后立即分析一次（联调用）
```

按 `Ctrl+C` 停止。

## 报警机制

这是本项目的核心设计，说明「画面很乱却不报告」和「正常画面乱报警」这两类问题是如何被同时压住的。

### 1. 视觉判定：双意见而非一票否决

初判报异常后，系统会取一次**独立第二意见**（提示词明确要求它独立观察、不迎合初判）：

- 两次都判异常 → 确认，并给一致性加成
- 意见分歧 → 保留为「疑似异常」，由本地活动度裁决是否否决
- 复核调用失败 → 不否决初判，按初判结果继续（宁可多提醒，不可漏报）

### 2. 本地兜底守卫：判断「模型说正常」可不可信

早期版本用「画面活动度超过固定阈值」来兜底，实测不成立——正常场景与混乱场景的活动度数值域**完全重叠**：

| 场景 | 活动度 | 是否真异常 |
| --- | --- | --- |
| 放教学视频 | 0.98 | 否 |
| 开灯 / 曝光渐变 | 0.82 | 否 |
| 正常上课、老师走动 | 0.47 | 否 |
| 多人离座打闹 | 0.95 | **是** |

调任何阈值都只能在「误报」与「漏报」之间二选一。因此改为四重过滤：

1. **空间聚集度**：整屏均匀变化（视频、噪点、压缩伪影）直接排除，只保留局部聚集性活动
2. **光照排除**：整幅图同向变亮/变暗属曝光变化，不视为混乱
3. **自适应基线**：先学习本场景自己的正常活动水平，用 z-score 判定偏离。老师持续走动会被吸收为常态，突然打闹则立刻捕捉
4. **模型可信度反向调节**：模型越确信「正常」，兜底门槛越高——相信模型，但不盲信

另外，模型回复「看不清 / 无法判断」被单独识别为**画面质量问题**，只给信息性提示，
不伪装成告警写入历史。

> **一个有意的设计取舍**：兜底需要先观察约 12 帧（约 1 分钟）建立基线才能工作。
> 因此刚启动就遇到混乱时不会立刻提示——宁可晚一分钟，也不愿在开局凭空告警。

### 3. 多轮复演：判断权在模型手里，不在规则表里

单帧画面里，「一群人围在一起看刚贴出的通知」和「一群人聚在一起打闹」几乎长得一样。
区别不在画面里，在**时间里**。所以初判说要告警时，系统不直接报，而是开一场复演：

| 角色 | 它负责回答 |
| --- | --- |
| 行为观察员 | 画面里到底发生了什么 |
| 情境解读员 | 结合记忆，这有没有别的解释（**唯一读取记忆的角色**） |
| 时序推演员 | 是在往严重演化，还是在平复 |
| 审慎质疑员 | 有没有可能是正常教学活动 |

四位各自独立看同一帧并给出「异常 / 正常 + 把握程度」，按把握加权投票。
**这里没有任何硬编码的类别规则表**——判断权完全在模型手里，基础系统只负责安排它怎么看
（给谁看、看几帧、带什么记忆）。

几条刻意的设计约束：

- **只在初判要告警时才开庭**，不浪费 API 调用
- **弃权好过乱投**：某位输出被截断时先重试一次（要求跳过推理直接给结论），重试仍失败才弃权
- **出席率参与置信度折算**：只到了 1/4 位时，置信度会被打到约 0.19，够不着告警阈值——
  避免「一个人的意见伪装成一致通过」
- **读记忆的角色给更大输出预算**：它的提示词最长、推理链最长，最容易被截断，
  而它偏偏掌握着「墙上刚贴了新表」这类关键证据。实测它一弃权，其余三位就只能
  就画面本身投票，把围观通知误判成异常

### 4. 外部记忆：让 AI 对这间教室了然于心

记忆分两套，职责严格分离：

| | 观测日志 | 环境文件 |
| --- | --- | --- |
| 记什么 | 发生了什么 | 由此我们知道什么 |
| 性质 | 只增不改，不可变证据链 | 持续修订，可错的知识库 |
| 能否追溯 | 任何结论都能追到原始记录 | 结论被推翻时留痕 |

**为什么必须分开**：时间一长就分不清「系统实际看到了什么」和「系统自己总结成了什么」。
一旦总结错了，还没法回到原始记录纠偏。分离是纠错能力的根基。

日志分四层（帧级 / 事件级 / 告警级 / 纠正级），**只写观测不写推断**——
不写「张三在玩手机」，只写「手部区域出现手持矩形反光物」。
需要审计时，这本身就是合规凭证。

记忆写满会自动压缩（保留结论、丢弃细节），并定期用最新观测重新校验旧结论，
置信度低的主动降级——**知识必须可老化，否则记忆会变成偏见**。

### 5. 场景变化检测：不是「画面动了」，而是「这里多了东西」

早期用感知哈希判断场景变化，实测失效：加一张分组表，哈希距离只有 1，
比正常画面抖动（距离 3）还小——整幅图的均值被课桌和人占满，一小块张贴物撬不动全局阈值。

换个思路：**张贴物是「同一小块区域每帧都在变」，抖动是「每帧变的地方都不一样」**。
用「持续性 + 紧凑度」双判据重写后，7 个测试场景全部判别正确。

## 隐私与合规提醒

- 教室画面可能包含未成年人，属于敏感个人信息。本工具所有图片只发往智谱官方 API 且不落盘到云，
  但**使用前务必取得学校/家长授权**，并建议：抓帧间隔不要太密、画面只保留必要区域、告警帧默认不落盘。
- 视觉模型存在漏报与误报，请勿将其作为唯一判据。

```
│   ├── md_memory.py         # 外部记忆读写与压缩（Markdown）
│   ├── memory.py            # 观测日志 + 事件生命周期追踪
│   ├── environment.py       # 环境文件（场景基线、区域、课程表）
│   ├── indexer.py           # 时间 / 空间 / 语义三层索引
│   ├── alert_history.py     # 告警历史持久化
│   ├── notifier.py          # 桌面通知 + 日志
│   └── selftest.py          # 六项自检
├── gui/
│   ├── main_gui.py          # 图形界面入口（pywebview 桥接）
│   └── web/                 # 本地前端（HTML/CSS/JS + GSAP，无外链）
├── tests/                   # 单元测试
└── tools/                   # 开发辅助脚本
```
